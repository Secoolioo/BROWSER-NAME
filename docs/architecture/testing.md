# Test strategy

> **Status:** approved design, not yet implemented. This page describes how Lampo is designed to be tested and will be updated as the test suites land.

Every change ships with tests at the right level. The strategy is designed so that a green `ci-gate` means the packaged app installs, starts, stays within its performance budgets and keeps its security guarantees on Windows, macOS and Linux, and that it updates through NSIS on Windows and AppImage on Linux; release runs add the updater tests for every package format. The decision record is ADR 0022 (test strategy); see the [decision record index](../adr/README.md). Every M1 acceptance criterion is an automated test unless marked otherwise; the M1 scope is described in the [roadmap](../roadmap.md).

Module tests live in each module's `__tests__/` folder. The other suites will live in `app/tests/`: `e2e/`, `perf/` (including the bare Electron reference), `smoke/`, `updater/`, `screenshots/` and `fixtures/` (local sites and golden profiles).

## Special cases

- **Sandbox tests.** The AppArmor and user-namespace tests will run on the host runner `ubuntu-24.04` with `sysctl kernel.apparmor_restrict_unprivileged_userns=1`, not in a container. The expected result: deb and rpm packages run with the Chromium sandbox, and the AppImage shows its fix page. Containers are used only for installation, dependencies and upgrade order.
- **Drag and drop between windows.** Playwright mouse actions are bound to a single page (as of October 2026). The hit-test and drag-session logic is therefore covered by unit tests, and the end-to-end tests drive the drag across two windows with `webContents.sendInputEvent`.
- **Documentation coverage.** TypeDoc will run with `entryPointStrategy: expand` over `app/src`, so every public class and method is checked for a doc comment.
- **One fuse apart.** Playwright needs the `nodeCliInspect` fuse enabled (as of October 2026), while the shipped build disables it. The end-to-end tests therefore run on the test build, and the shipped package is checked through its built-in self-test (`--smoke-test`) and by reading its fuses.

## Manual checks per minor release

A few checks need people. Maintainers perform them once per minor release, not per patch, and record the result as described in [WORKFLOW.md](../maintainers/WORKFLOW.md). They include the screen reader smoke test with NVDA, VoiceOver and Orca, the import of the ADMX templates into Microsoft Intune, and the design review of the generated screenshot gallery. The complete list is kept in WORKFLOW.md only.

## Rules

- **No skipping.** Tests are never skipped or disabled, and there is no quarantine.
- **Zero retries.** Playwright runs with 0 retries in CI. A flaky test is fixed immediately and takes priority over other work. The one automatic rerun that the performance harness allows before a budget check fails is part of its measurement method, not a test retry (see [performance.md](performance.md)).
- **Own fixtures.** Tests use their own test pages, served locally: deterministic and free of third-party brands.
- **Golden profiles from the release preparation step.** The golden profiles for migration tests will be created by `pnpm release:prepare` in the release pull request that a maintainer authors, not by a workflow (see [data.md](data.md)).
